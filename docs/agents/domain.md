# Domain docs

## Layout

This is a single-context repository:
- `GLOSSARY.md` at the repository root.
- Architecture decision records under `docs/adr/`.

## Consumer rules

Before exploring domain behavior, read the glossary and relevant ADRs
when present. If absent, proceed silently; create them lazily through
domain modeling when terminology or architectural decisions are resolved.

Use glossary vocabulary in tickets, proposals, and tests.
Explicitly flag proposals that conflict with an existing ADR.
